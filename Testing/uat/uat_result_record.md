# iRonda UAT result record

Version 2 | Updated 8 September 2026 | Awaiting recorded sessions

This empty template contains no respondent counts, scores or acceptance claims. Follow [the current protocol](uat_protocol_and_questionnaire.md) and retain actual Google Forms responses separately. Do not estimate missing results.

## Evaluation round

Record round ID, instrument version, dates, facilitator ID, app build/revision, API revision, database baseline, device/Android version, language, network and local/online environment. Record recruitment target, essential roles/tasks and acceptance criteria before testing.

|---|---|---|---|---|---|---|---|

One row per person per evaluation round. Record observers separately. Exclude No-consent submissions from respondent analysis. Collect no personal identifiers beyond the assigned code.

## Task observations

| Participant ID | Task ID | Attempt or round | Outcome | Start | End | Elapsed seconds | Help given | Issue or block reason | Evidence reference |
|---|---|---|---|---|---|---|---|---|---|

Outcomes: Independent, Assisted, Not completed, Blocked, N/A. Explain Blocked and N/A. Preserve first attempts and retests separately.

## Questionnaire data

Retain the original form export and an analysis copy. Link by participant code and round. Preserve A01 to A10, S01 to S10, F01 to F04 and O01 to O04. Ratings are 1 to 5, not 1 to 10. A/F questions allow N/A; SUS questions do not. Skipped items remain missing, not zero. Review duplicate participant codes; do not count repeat submissions as additional people.

## Feedback and defects

| Issue ID | Anonymous participant reference | Task or comment ID | Observation or suggestion | Severity | Action | Status | Retest evidence |
|---|---|---|---|---|---|---|---|

Distinguish user opinion from observed malfunction. Retain unresolved issues and contrary feedback. Record a fix as retested only with actual retest evidence.

## Calculations and reporting

- Count unique consenting task participants, questionnaire respondents, withdrawals and observers separately.
- Chart actual background and assigned role separately with explicit denominators; avoid identifying small groups.
- Calculate combined and independent task completion using the protocol definitions. Disclose blocks, failures, N/A and exclusions.
- Show valid, missing and N/A counts for each A/F item and the distribution of ratings 1 to 5.
- Calculate a participant acceptance mean only with eight or more valid A answers, then average eligible participant means.
- Calculate SUS only with ten valid S answers using the protocol formula. Report complete sample and incomplete exclusions; do not label SUS as a percentage.
- Keep feature feedback separate from acceptance, SUS and observed task results.
- Check actual sample and essential role/task coverage against the plan. Document deviations and limitations.
- Evaluate each project target and record Accepted within evaluated scope, Not accepted, or Incomplete with evidence.

## Report outputs awaiting evidence

Participant profile chart; task completion chart; acceptance response distributions; SUS summary; feedback and improvements table; decision with limitations. Populate only after actual responses and task records exist.
